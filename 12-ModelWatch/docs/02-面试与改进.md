# 面试怎么讲，以及下一步怎么做

## 60 秒介绍

“我复现了 Evidently 官方的数据漂移示例，并扩展成一个离线模型监测项目。项目用原创合成数据训练逻辑回归，把训练、参考和当前批次分开，模拟正常、采集值偏移、标签关系变化三个场景。报告同时观察输入 PSI 和分类效果，能够展示‘没有输入漂移也可能预测变差’。我补了 Windows 运行入口、依赖锁定、中文总览、数据隔离与指标一致性测试。底层统计和可视化来自 Evidently，模型训练来自 scikit-learn。”

上面描述的是完成后的项目内容。实际面试时请根据自己的掌握程度，清楚说明 AI 辅助和开源复用部分；没有亲自做过的训练调优或上线工作不要认领。

## 常见追问

**为什么不能把训练集直接当监测参考？**

训练样本上的预测可能偏乐观。这里用独立参考批，训练阶段没有看到这批数据。真实业务还要讨论时间切分、标签延迟和代表性。

**为什么概念变化时 PSI 不告警？**

PSI 只比较各输入列的边际分布。本例输入没变，但标签和输入之间的关系变了，必须检查带真实标签的效果，或用其他信号进一步调查。

**为什么传感器偏移 AUC 没下降？**

当前模型是线性逻辑回归，所有样本的同一输入加固定数，使线性打分增加常数。排序不变，因此 AUC 不变；固定分类阈值与预测概率却受影响。

**会自动重训吗？**

不会。先判断问题来自数据管道、标签、分布还是模型，再决定修复或重训。采集值偏移可能需要修传感器/ETL；直接重训会把数据错误固化进去。

**这个数据能证明工业落地效果吗？**

不能。合成数据用于构造可控反例和验证监测链路。真实场景需要合法数据、时间分割、业务成本和阈值校准，不能把这里的 81.70% 当作工业模型指标。

## 五分钟演示顺序

1. 解释三个卡片与训练/参考/当前分工。
2. 展开传感器偏移中的 temperature 分布图，指出实际 PSI 和两列告警。
3. 指出标签关系反转的“0 列漂移、18.30% 准确率”。
4. 打开 `data.py`、`pipeline.py`，说明生成、训练、评价与工具边界。
5. 运行 `check.cmd`，展示隔离与真实指标检查，再说明当前局限。

## 适合自己继续完成的改进

- 增加第四种“标签延迟”模式：先只显示输入监测，标签到齐后再计算效果；没有标签时不要虚构准确率。
- 把合成批替换为合法的公开业务数据，用时间切分模拟线上输入，并补数据来源与许可。
- 加入缺失率、范围和重复值检查，区分数据质量错误与分布变化。
- 将固定阈值改为基于多批稳定历史数据选择，同时保留独立验证批。
- 保存按日期排列的监测记录，做趋势图；决定是否告警时考虑连续异常，减少短期波动误报。
