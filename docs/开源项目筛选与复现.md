# 面向实习的 GitHub 项目筛选与复现

日期：2026-09-28。背景：广东岭南职业技术学院人工智能技术应用专业，已有YOLO、BERT、SupportLab和ScanLab作品。用户明确要求寻找可复用项目，实际做一遍，并加入现有作品集。

## 本次选择

| --- | --- | --- |
| [RapidAI/RapidOCR](https://github.com/RapidAI/RapidOCR) | 中文OCR、CPU推理、可接人工校对，补充现有图像几何处理项目 | 复现官方入门调用，新增 `11-OCRDesk` 工作台 |

| [recommenders-team/recommenders](https://github.com/recommenders-team/recommenders) | 推荐系统包含数据、排序与评估，适合作为后续方向 | 本次仅检索候选，未复现；官方快速起步涉及不同环境与外部数据，留待单独项目 |

选择依据是与已有作品互补、在本机可复现、能解释清楚上游和自己的改动。这里没有依据最新招聘数据做岗位数量或薪资判断，也不保证凭项目即可进入某家公司。

## 实际完成的复用方式

两项上游均核验Apache-2.0源代码许可证，保留原文与版权。使用固定版本库及官方示例的调用方式，新增独立应用流程和实验；没有把上游整个仓库去掉作者后重新上传。模型二进制、虚拟环境、私有数据和缓存不进入作品集。

- OCRDesk：RapidOCR 3.9.2，Git提交 `095232a4c94f7f0e6600ba5bba1177010ad696d4`。上游工程负责识别，新增校对、结果溯源、API与导出。13项测试通过；5张同版式合成正例CER为0，空白负例没有输出，不能推断实拍准确率。
- ModelWatch：Evidently 0.7.23，上游示例来源固定至 `34771fe41c08ca074d96a52aaf4a45cd640cbaf5`。新增原创合成设备特征、独立训练/参考/当前批、三种场景、告警说明和中文报告。正常准确率81.7%、传感器偏移50.6%、标签关系反转18.3%；均为合成演示结果。

## 学习顺序

1. 先学OCRDesk：图片输入 → 模型输出 → 人工校对 → JSON/CSV。这个流程直观，容易逐段讲清楚。
2. 再学ModelWatch：训练与评估分离、参考批与当前批比较、数据漂移与效果下降的区别。
3. 每项至少独立做一处改进，留下代码提交、样本和前后指标。基础版本是AI辅助开发，个人贡献不能提前写成已经掌握。
