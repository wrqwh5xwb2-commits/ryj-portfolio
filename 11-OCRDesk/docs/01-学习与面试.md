# 第一课：把识别与正确区分开

## 先花10分钟操作

1. 选择中文清单，找到“笔记本”一行，点击左侧对应文字框。右侧输入框应定位到这一行。
2. 改成“笔记本（已核对）”，勾选已核对，下载JSON。找到 `original`、`text`、`reviewed` 三个字段，解释为什么要保留原文。
3. 再次修改该行，观察“已核对”自动取消。思考修改后是否仍应沿用之前的核对结论。
4. 调整阈值到0.99，勾选“只看低分”。分数低只是提醒你关注，不表示这行一定错；高分也不保证正确。
5. 选择空白图，观察没有文字时如何反馈。用自己拍摄的不含隐私的印刷文字继续测试。

## 按这个顺序读代码

| 阶段 | 文件与函数 | 要回答的问题 |
| --- | --- | --- |
| 上游复现 | `upstream/quickstart.py` | 哪两行代码调用了真正的OCR模型？ |
| 输入 | `app/ocr.py:decode` | EXIF方向、RGB/BGR和尺寸限制各解决什么问题？ |
| 推理 | `app/ocr.py:recognize` | 检测框、文字和分数如何逐行对应？ |
| API | `app/main.py` | 为什么图像计算放在线程池，模型又加了锁？ |
| 界面 | `static/app.js:renderRows` | 怎样避免把识别文字当HTML执行？ |
| 导出 | `app/ocr.py:export_csv` | 为什么以等号开头的识别结果要加保护？ |
| 评测 | `app/evaluate.py` | 插入、删除、替换如何变成CER？ |

检测先找到文字区域，方向分类判断文本行是否需要翻转，识别将图像序列变成字符。它们由上游模型完成。本项目重点是把模型输出接入可检查、可修正的完整流程。

## 三分钟面试演示

- 第一分钟：展示一张图从识别到校对再导出；说明模型是RapidOCR/PaddleOCR，自己展示的是应用工程。
- 第二分钟：讲解一行数据如何从API进入界面，再形成保留原文的JSON；展示CSV安全导出或一个输入边界测试。
- 第三分钟：展示评测数据和局限，说明合成集CER为0不能证明实拍效果。拿出你后来采集和标注的真实照片、改进提交与前后结果。

## 你自己的第一个改进

采集20张独立真实照片，按光照、角度和字体分组。人工写下真值，分开开发与评估图片。先运行原版，记录CER与失败原因，再选择一个改进，例如透视矫正后接OCR、加低分复核队列或支持双栏阅读顺序。

记录你写的代码、修改前后数据和仍然失败的图片。简历可写“基于RapidOCR完成本地识别与人工校对流程，新增……”，只有你亲手理解并实现的部分才能表述为个人贡献。
