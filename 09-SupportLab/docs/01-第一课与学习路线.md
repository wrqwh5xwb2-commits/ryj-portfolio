# 第一课：先把项目用明白

你现在不需要先背算法名。今天只要理解一句话：**客户提出问题，系统找资料并提出建议，客服核实后处理。**

## 用10分钟走完一次流程

1. 双击“启动项目.cmd”。在打开的页面点击“退款进度”，再点击“分析并查找依据”。
2. 找到“建议分类：退货退款”。分类模型像一个新来的分流员，读过96条带类别的例子，现在猜这个问题应该给哪组客服。
3. 看右侧第一篇“退款到账与进度查询”。检索器像图书管理员，只负责找可能有用的规范。
4. 核对左侧回答和右侧原文。第一版回答直接摘录原文，不是大模型临场编写。
5. 点击“转为人工工单”，确认分类与优先级后创建。工单就是一张要继续跟进的任务单。
6. 点击左侧“工单管理”，在备注中输入“已核实退款发起时间，等待银行入账”，再点“接单处理”。
7. 再写“演示：已向客户解释到账时间，问题解决”，选择“已关闭”，点击“更新状态”。这是模拟练习，没有真实退款发生。
8. 展开处理记录，确认创建、接单、关闭都有记录。
9. 返回工作台，点击“未知问题”并分析，观察系统为什么没有给天气答案。

## 现在停下来，试着回答三句话

- 分类模型负责什么？
- 右边规范和左边回答是什么关系？
- 系统建议分类错了，谁来决定最终工单分类？

参考答案：分类负责推荐处理组；右边是可核实的原文、左边是其中一篇的摘录；由人确认和调整。能用自己的话解释，比照着背定义更有用。

## 第一次亲手改变系统

1. 打开“知识库”，选择文件 `examples/member-policy.md`。
2. 标题填“会员积分兑换规范”，业务类别选“支付订单”，点“保存并更新索引”。
3. 回到工作台输入“会员积分兑换比例是多少”。
4. 检查第一条来源是否是你刚添加的规范，回答是否包含“每100积分可以兑换1元优惠券”。

你刚完成了第一个改动：给系统增加知识。**这不会给分类模型增加第7个类别，也不会重新训练模型。** 理解这一区别，就迈过了重要的一步。

## 第二课预告：读懂一个字典

打开 `app/dataset.py`，找到 `TRAIN`：

```python
TRAIN = {
    "退货退款": ["我想退货退款", "退款多久能到账"],
    "物流配送": ["快递到哪里了", "包裹一直没更新物流"],
}
```

这里是结构示意，原文件内容更多。外层大括号是字典，左侧文字是类别，右侧列表是这个类别的示例。模型训练时看到的是“句子 + 正确类别”配对。

你的练习：自己写三个属于“物流配送”的句子，再写一个容易与“退货退款”混淆的句子。不要马上改测试集，先解释为什么这样分类。

## 常见困惑

**页面打不开：** 再双击启动入口，看终端错误。若8765端口被其他程序占用，在项目终端运行 `.\.venv\Scripts\python.exe launch.py --port 8766`。

**改训练数据后没变化：** 关闭服务并重新启动，当前分类模型在启动时训练。

**知识添加后分类仍然错：** 知识库和分类训练集是两个不同的数据源。

**界面有小样本高分，是不是很厉害：** 高分只说明在这些题目上表现不错，需要换一批独立问题检验。

**看不懂一大段代码：** 每次只找一条请求经过的函数，先会读输入和输出，再理解实现。
